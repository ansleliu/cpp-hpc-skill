# Astra Skill Evaluation, 2026-09-08

## Scope

This is a bounded instruction smoke comparison, not a performance benchmark or a statistical model-quality evaluation. The main skill remains model-independent. Guidance was checked against the [official GPT-6 Astra guide](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra).

- Model: inherited GPT-6 Astra; reasoning effort explicitly set to medium for both arms.
- Baseline: commit `a54832f71e664402f105ec0f2c185b7d9bfded05`.
- Candidate: the entrypoint and methodology revision in this change.
- Four fresh agents: one attempt per arm for each of two cases, with no parent conversation fork.
- Same prompts, fixture contents, and shared Windows host; only arm-specific paths and skill contents differed.
- No network, installation, hardware timing, external writes, or Git operations were allowed in the cases.
- Agents could write only in their own repair directory; the review case was read-only.
- This did not isolate host/global instructions, test implicit discovery, or reproduce a real multi-turn authorization history.

## Case 2: Static Read-Only Review

Create `kernel.cpp`:

```cpp
#include <cstddef>

struct Sample {
    double position[3];
    double weight;
    double unused[12];
};

double total_weight(const Sample* samples, std::size_t count) {
    double total = 0.0;
    for (std::size_t i = 0; i < count; ++i) {
        total += samples[i].weight;
    }
    return total;
}
```

Exact task prompt with the same path substitutions:

> Use $cpp-hpc-performance-engineering at SKILLPATH for the task below. Inspect CASEPATH/kernel.cpp for C++ HPC memory-access and vectorization opportunities. The target compiler, target hardware, profiler and runtime benchmark are unavailable. Give a source-grounded diagnosis and reproduction steps in Chinese. This is a read-only review; keep all files unchanged. Do not install tools, use network services, or read unrelated workspaces.

Inspect whether the answer distinguishes potential strided-load/locality costs from measured bottlenecks, respects floating-point reduction semantics, accounts for conversion costs, and provides target-side reproduction steps. Check that the source and directory contents remain unchanged.
